# Submitted NCSC assessment results

NCSC-006 presents a saved submission immediately after acknowledgement and when
reopened through PR229's authenticated assessment journey. It uses PR231's focus
repair. Results do not grant access, submit another command, update an answer,
create an improvement action or produce a report.

Four measures remain separate:

- Implementation attainment: the server's weighted lower/upper percentage range.
  Unknown answers and pending N/A claims remain uncertainty, not implementation.
- Evidence confidence: explicitly not assessed. Substantiated and tested coverage
  display the server values; self-attestation is not proof of effectiveness.
- Risk priority: explicitly not calculated because the current evaluator requires
  a separate priority adapter. Suggested actions are in framework order.
- Trend: no comparison available. The current submission requests no comparison;
  a new trend needs the appropriate version/scope comparison contract.

Native expandable domain and control panels show attainment, saved answers,
pending N/A rationale, evidence state, weight, suggested actions and evidence
examples from the accepted metadata. The calculation panel exposes the submitted
revision/time, framework/profile versions, evaluator and contract versions,
mapping/weight versions, input/snapshot fingerprints and output SHA-256. It does
not treat fingerprints as access tokens, downloadable files or independent proof.
The saved scope and unchanged attribution/limitations remain available.

## Validation and trust boundary

`resultModel(assessment, metadata, organisationId)` in the existing protected questionnaire module
projects only consumed display fields. It checks profile, assessment/revision/time
bindings against the authenticated selected organisation, complete domain/control/question membership, saved-answer mapping,
percent display/range shape, aggregate totals and coverage against atoms, known evidence vocabulary and the current absent
risk/trend states. Consistency validation checks credit totals and the integer rounding interval but never supplies a replacement score or falls back to locally edited answers. The server continues to own
arithmetic, canonical hashing, tenant authorisation and durable input validation.
The view is not an independent cryptographic verifier of server output.

A malformed or unsupported evaluation produces a fixed results-unavailable message
while retaining acknowledged submitted answers. This cannot turn an acknowledged
submission into an ambiguous write or trigger a duplicate submit. Late responses
are discarded through the unchanged mount-generation checks. Disposal, forced
tenant changes and denied access clear the result with all other assessment data.
No record-bearing browser storage, URLs or network paths are added. All dynamic
content is inserted with textContent, including untrusted rationale text.

## Acceptance and preview

The local structural suite covers create/answer/submit/results/reopen, all response
types, the independently specified mixed golden range46.4%–60.7%, pending N/A,
invalid result fallback and stale-tenant response disposal. These are not browser
observations or physical-mobile tests.

The existing offline preview can show real precomputed results by opening its
seeded `assessment-submitted` record. Interactive synthetic submissions deliberately
have no genuine evaluation and therefore show results unavailable; do not copy or
invent figures for them. The actual handler-backed tests exercise new submissions.
The fixture builder does not serve or publish the document.

Native desktop and320/390px keyboard/reflow acceptance remains Not Run under the
recorded preview URL-policy restriction. Before closure, use a permitted browser
test environment to check native disclosure controls, focus, long fingerprint and
rationale wrapping, all four measures, save/resume, uncertain-write reconciliation,
leave cancellation and forced tenant changes. DOM/CSS/build results cannot close
NCSC005-AC03. The separate release freeze, runtime/PostgreSQL activation and
first-customer admission gates remain unchanged. No deployment is claimed.

The current submission adapter has no approved N/A decision registry. Unsupported approved exclusions fail closed until explicitly supported. Aggregate validation rejects impossible counts, mismatched populations/coverage, inconsistent overall/domain/control credit and impossible percentage rounding. Display values always remain the acknowledged server values.

The supported calculation dialect is pinned to evaluator2026-09-02.1, its reviewed source digest, decimal-half-up-one-place-v1 and the current mapping/weight versions. Unsupported versions show results unavailable instead of mislabelling figures checked under another algorithm.

Each question must retain weight1 from the pinned accepted profile. Consistently altered payload weights and aggregates do not establish a different authorised weight set.

This saved-assessment store creates and retains not_provided evidence only. The projection refuses any other atom evidence state even when its coverage/distribution is internally consistent. Supporting collected evidence later requires an explicit trusted snapshot binding; this view cannot manufacture attestation, substantiation or independent review.

The supported evidence/risk snapshot-body digests and mapping, weight-set, scored-atom-set and empty approved-applicability-basis digests are pinned to the canonical accepted evaluator's current adapter defaults. Well-formed alternate fingerprints are rejected. Variable record references and output fingerprints remain the server's references; the view does not independently certify their authority.
